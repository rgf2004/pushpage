HTML hosting for AI agents

AI agents now produce rich HTML: reports with tables and charts, interactive dashboards, prototypes. Chat is a poor place to read or share any of that. The missing piece is a place to put the page and a link to hand back.

Why chat is the wrong place for HTML

  • Walls of text. Markdown pasted into chat is a flat approximation. HTML can carry layout, tables, charts and interaction.
  • Hard to share. A link gets opened and reviewed. A pasted block or an attachment mostly does not.
  • Hard to update or remove. A published page has an address you can send, replace or delete.

What an agent needs from hosting

  1. No deploy step. The agent should publish with one call, not a build and a push.
  2. An instant URL. The result must come back immediately so the agent can pass it on.
  3. Agent-friendly access. A simple HTTP API, plus an MCP server for clients that support it, with keys that can be created per agent and revoked on their own.
  4. Sensible lifetimes. Temporary by default, so forgotten pages clean themselves up.
  5. Containment. Pages are untrusted content written by a model, so scripts on them must not be able to touch the service itself.

How pushpage does it

pushpage is an HTML publishing service built for this. One request publishes a page:

curl -X POST https://pushpage.link/api/pages \
  -H "Content-Type: application/json" \
  -d '{"html":"<h1>Q2 report</h1>","title":"Q2 report"}'

The response holds the shareable url, the page id and an expiry time. You can also upload a file with multipart/form-data, or let an agent do it through the MCP server.

  • Try without an account. Guest pages need no key and are deleted after 30 minutes. An account gives longer retention and lets you list and delete pages.
  • Named keys. Create a key per agent or tool; revoke one without breaking the rest.
  • Sandboxed pages. Pages are served with a security policy that lets their own scripts run but blocks access to the dashboard and the API.
  • Open source. MIT licensed, and self-hostable with Docker Compose (self-hosting).

When pushpage is the right tool

pushpage is for single, self-contained pages that an agent produces on the fly: a report, a dashboard, a prototype, a summary. If you need a full website with a build pipeline, custom domains and many linked files, a conventional static host is the better fit.

Things to remember

  • Pages are public. Anyone with the link can open a page. Do not publish secrets or private data.
  • Write self-contained HTML: inline styles and scripts, and a <title> in the head.
  • There is a size limit per page (1 MB by default).

Get started

Add it to Claude Code with one command, or read the documentation:

claude mcp add --transport http pushpage https://pushpage.link/mcp-guest
