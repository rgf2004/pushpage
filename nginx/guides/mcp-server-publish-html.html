An MCP server that publishes HTML

The pushpage MCP server gives an AI agent one job it is usually missing: turn the HTML it just wrote into a link someone can open. It is hosted, free to try without a key, and also installable locally.

What it is

An MCP server with four tools: publish_page, list_pages, delete_page and health. The agent sends HTML and receives a public URL. The hosted endpoint is https://pushpage.link/mcp (streamable HTTP). It is listed in the official MCP Registry as io.github.rgf2004/pushpage.

Two ways to connect

Guest mode (no key)

Connect with just the URL. publish_page works and the page is deleted after 30 minutes. The tool result tells the agent (and you) to sign up or sign in for an API key if you want more. list_pages and delete_page need an account.

With an API key

Create a named key under Account in the dashboard, then send it as X-Api-Key or Authorization: Bearer. Pages then follow your account's retention, and all four tools work. A wrong key is rejected with a 401; it is never silently treated as a guest.

Claude Code

# try it, no key
claude mcp add --transport http pushpage https://pushpage.link/mcp-guest

# with your key
claude mcp add --transport http pushpage https://pushpage.link/mcp \
  --header "Authorization: Bearer pp_your_key_here"

Cursor

Add this to ~/.cursor/mcp.json (or your project's .cursor/mcp.json) and restart Cursor. Omit the headers block to use guest mode.

{
  "mcpServers": {
    "pushpage": {
      "url": "https://pushpage.link/mcp",
      "headers": { "X-Api-Key": "pp_your_key_here" }
    }
  }
}

One-click install (Cursor and VS Code)

These buttons add pushpage with browser sign-in, so no API key is involved: the app asks you to confirm, then opens your browser to sign in with your pushpage account the first time it connects. They need the desktop app installed.

Add to Cursor Add to VS Code

Self-hosting? The dashboard (Account tab) shows the same buttons pointing at your own instance.

Claude Desktop

Claude Desktop does not always forward custom headers to remote servers, so use the mcp-remote bridge (needs Node.js). Add this to claude_desktop_config.json and restart the app:

{
  "mcpServers": {
    "pushpage": {
      "command": "npx",
      "args": ["mcp-remote", "https://pushpage.link/mcp",
               "--header", "X-Api-Key:pp_your_key_here"]
    }
  }
}

Run it locally instead

If you prefer a local process, the server is on PyPI as pushpage-mcp. With uv installed:

claude mcp add pushpage -e PUSHPAGE_API_KEY=pp_your_key_here -- uvx pushpage-mcp

It speaks stdio, works as a guest without a key, and can point at your own server with PUSHPAGE_URL. Setting PUSHPAGE_PUBLIC_URL as well makes the sign-up links in guest messages point to your instance.

Troubleshooting

  • 401 “Invalid or expired credentials”: the key is wrong or was revoked. Create a new one in the dashboard.
  • The key never arrives (Claude Desktop): use the mcp-remote configuration above.
  • Tools do not appear: restart the client after editing its configuration, and check the server shows as connected.
  • Self-hosting: see the self-hosting guide; the MCP server runs in the same Docker Compose stack.

Try it now

No account needed. Add the server to Claude Code and ask for a page:
